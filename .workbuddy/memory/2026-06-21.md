## 修复：计时结束卡在 0 秒，无法触发提醒/进入休息

**症状**：focus 倒计时到 0 秒后 UI 卡住，无提醒声、无震动、不进入休息阶段。日志停在 `startFocus: creating new session` 之后。

**根因**：`TimerViewModel.finishSessionInternal` 中 `timerEngine.stop()` 取消的是**当前正在执行的协程**（engine job），导致后续所有 suspend 调用（`updateSession`/`appendLog`/`notifyFinish`/`_effects.emit`/`completeFocus`）抛 `CancellationException`，被 `runCatching` 或 catch 吞掉，协程静默结束。数据库 session 仍是 RUNNING/0秒。

**调用链**：
```
MonotonicTimerEngine.job (循环)
  └─ onTick(0) → handleTick (stateMutex.withLock)
       └─ finishSessionInternal
            ├─ timerEngine.stop()  ← job.cancel() 自取消
            └─ updateSession/notifyFinish/emit/completeFocus  ← 全部 CancellationException
```

**修复**（`app/src/main/java/com/xuweikai/tomatoclock/feature/timer/TimerViewModel.kt`）：
- `timerEngine.stop()` 之后的所有 suspend 逻辑用 `withContext(NonCancellable) { ... }` 包裹
- 保证 finish 流程（DB 更新 COMPLETED、提醒、事件下发、创建 break session）原子完成
- 其他调用 `timerEngine.stop()` 的地方（`confirmReset`/`pause`/`resume`）在 `viewModelScope.launch` 新协程中执行，无自取消问题，不需要改

**关键文件**：
- `core/domain/timer/TimerEngine.kt`：`MonotonicTimerEngine` 用 `scope.launch` 启动循环 job
- `feature/timer/TimerViewModel.kt:322-371`：修复后的 `finishSessionInternal`
- `app/src/test/.../TimerViewModelTest.kt`：`FinishableTimerEngine.finishByTick` 同样在 job 协程中调用回调，修复前测试也会暴露此 bug
